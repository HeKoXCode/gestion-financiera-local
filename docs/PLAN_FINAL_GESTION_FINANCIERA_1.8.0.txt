Fecha de trabajo: 29/09/2026

OBJETIVO
-------

Unificar la edición local 1.7.2 con la edición 1.1.0 publicada en GitHub sin
perder funciones, datos compatibles ni el historial del repositorio. La salida
debe ser una versión 1.8.0 gratuita, reproducible, verificable y publicable.

DECISIÓN DE PRODUCTO
--------------------

Distribuir la aplicación completa y gratuita bajo MIT.

No implementar un límite artificial de clientes mediante un archivo cifrado
local. Al publicar el código, la clave y la validación también quedarían en el
equipo del usuario; el límite sería evitable, agregaría estados de error y
debilitaría la reproducibilidad del portfolio sin constituir una licencia
robusta.

La demostración no será una versión recortada. Será la aplicación completa con
una base ficticia separada, reversible y claramente identificada. Si en el
futuro existe una edición comercial, conviene vender instalación, soporte,
hosting o una edición profesional con servicio remoto y licencias firmadas.

CRITERIOS DE ACEPTACIÓN
-----------------------

- Ninguna función documentada de 1.7.2 o 1.1.0 desaparece sin justificación.
- Una instalación local existente conserva sus datos al actualizar.
- El perfil local no exige login y el multiusuario sí lo exige.
- El cobrador no puede configurar, corregir, cancelar, anular, respaldar ni
  consultar la auditoría.
- La analítica y el data mart usan el mismo motor financiero y concilian.
- El repositorio no contiene datos reales, contraseñas ni artefactos generados.
- Los dos ZIP se validan desde una extracción limpia.
- README, versión, changelog, tag, nombres de ZIP y hashes coinciden.

ROLLBACK
--------

Si falla una migración o el smoke test, no reemplazar ninguna instalación.
Conservar el tag anterior, corregir en el clon y repetir QA. Para una base real,
crear primero un backup verificado, cerrar normalmente la aplicación y probar
la actualización sobre una copia. Nunca reemplazar data/, backups/, exports/,
media/ ni storage/ con el ZIP de actualización.
